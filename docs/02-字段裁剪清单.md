# New_AOM 字段裁剪清单

> 依据 [01-系统改造建议.md](01-系统改造建议.md)，对 SN-AOM 实际模型逐字段标注处理方式。
> 字段名/类型/注释均取自 `SN-AOM/mcp_servers/db/models/`（实测，非估计）。

**处理方式图例**：

- **必填** — 创建表单必填项
- **可选** — 创建表单可选项（默认折叠在"更多"里）
- **阶段** — 不在创建表单，生命周期后续阶段填写（如解决时、关闭时）
- **条件** — 仅特定类型时展示（如工单选 change 类型）
- **自动** — 系统生成/计算/带出，无录入入口
- **删除** — 新系统不要此字段

## 8. 成长积分：growth_record(27) + innovation_idea(10) → 自动流水 + 极简建言

旧模式的问题：`growth_record` 要求成员手工申报 27 字段（问题描述/方案/提升比例/可复制性/字数/实用性/创新性/演示效果打分/月度/季度…），再走评审打分——录入和评审负担都重。

**新模式：积分不录入，由各域事件自动产生。**

### 8a. point_rule 积分规则（管理员配置，~6 字段）

| 字段 | 处理 | 备注 |
| --- | --- | --- |
| rule_code / name | 配置 | 如"工单按时解决" |
| event_type | 配置 | 见下方事件清单 |
| points | 配置 | 分值（支持负分） |
| active | 配置 | 启停 |

**自动触发的积分事件**（分值全部可配）：

| 来源 | 事件 |
| --- | --- |
| 服务贡献 | 工单解决、SLA 双达成、满意度好评、问题根因定位 |
| 项目贡献 | WBS 任务按期完成、里程碑交付 |
| 需求贡献 | 需求任务完成、需求整体关闭 |
| 培训贡献 | 主讲/组织培训、参与培训 |
| 知识贡献 | 发表知识文章、文章被点"有用" |
| 建言献策 | 提出建言、建言被点赞、建言被采纳 |

### 8b. point_entry 积分流水（全自动，零录入）

person / event_type / points / source_ref（触发实体 GLID）/ earned_at / remark。管理员手工加减分也走流水留痕。排行榜、个人积分、月度趋势全部实时聚合流水，无预计算表；积分汇总同时作为人效评价输入源之一。

### 8c. idea 建言献策（替代 innovation_idea，录入 2 项）

| 字段 | 处理 | 备注 |
| --- | --- | --- |
| title | **必填** | |
| description | **必填** | |
| idea_code / submitter / status / like_count | 自动 | status：已提交/已采纳/已实现，管理员流转 |
| category / business_case / expected_impact / pilot_results / champion | 删除 | 商业论证装置砍掉，采纳后的落实走需求或项目 |

`idea_like`（idea_id + person，防重复点赞）支撑点赞积分。

**growth_record 27 字段全部删除**：效率案例/知识输出类内容改由知识库文章承载（发表即得积分），AI 演示/技术研究由培训发展 `development_activity` 承载，评审打分装置（practicality/innovation/presentation_quality/grade/score/composite_score/review_status/approval）不再需要——积分规则自动计价。
