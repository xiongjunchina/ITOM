# IT运营管理平台用户操作手册

> 适用版本：当前代码版本（2026-07-30，Aily-MCP P2.1）
> 适用对象：业务用户、IT 团队成员、专业线/服务线负责人、CIO、系统管理员

## 使用帮助中心

帮助中心采用“搜索优先、按模块浏览、文章内目录”的文档结构，适合先定位问题再阅读完整流程：

1. 登录后点击右上角语言切换按钮左侧的 **操作手册**，进入帮助中心首页。
2. 在顶部搜索框输入模块名称、字段名称、操作动作或错误提示；搜索结果会按匹配文章展示。
3. 也可以从“按产品浏览”选择 ITSM、项目管理、需求管理、团队管理、流程中心或系统管理，按模块查看热门指南和最近更新。
4. 打开文章后，右侧“本文目录”可直接跳到运作逻辑、操作步骤和角色边界；点击“返回帮助中心”继续浏览其他文章。
5. 文章中的按钮、字段和可见范围以当前账号权限为准；中文是产品与技术契约的权威版本，英文页面同步提供对应内容。

## 1. 系统总体介绍

IT运营管理平台（ITOM）用于统一管理 IT 服务、项目、需求、团队能力与流程治理。系统采用“业务域 × 专业线”的矩阵式组织方式：

- **横向业务域**：面向供应链、产品、销售等业务部门提供服务，配置服务线负责人（BM）、备份负责人、服务部门和服务团队。
- **纵向专业线**：通过用户组和角色组织研发、运维、项目管理、产品、数据、安全等资源池。
- **流程驱动**：服务请求、事件、变更、问题、需求和项目等单据按流程推进状态，处理节点与审批节点分开管理。
- **统一数据范围**：涉及人员选择的字段默认只展示已配置的数字化团队成员；组织架构由飞书或其他集成源同步，管理员可组合选择数字化团队部门和具体人员。
- **周期化绩效**：人效评分按季度（Q1/Q2/Q3）或年度周期运行，角色贡献、团队贡献、外部满意度和学习成长积分分别取数后汇总。

### 1.1 登录与账户

1. 使用用户名/密码登录；也可以使用飞书认证（如果管理员已经启用）。
2. 飞书新用户先完成身份验证，再等待管理员在“系统管理 → 用户与组管理 → 登录开通”审批。
3. 管理员批准开通时生成 12 位初始密码。管理员可在用户详情中查看或手动发送邮件；用户首次登录后应在“个人中心 → 安全设置”修改密码。
4. 右上角可切换中文/English、查看通知、进入个人中心和退出登录。
5. 右上角语言切换按钮左侧的 **操作手册** 可随时打开本页面。

### 1.2 通用列表操作

系统中的业务表格遵循统一交互规则：

- 使用关键字搜索框查找编号、名称、标题等核心字段。
- 使用筛选下拉框按状态、类型、业务域、负责人等关键字段过滤。
- 点击表头字段进行升序/降序排序。
- 使用分页器切换 10/20/50/100 条每页；服务端列表会将页大小传给后端。
- 表格超出内容区域时，底部会保留横向滚动条；页面向下滚动时表头保持可见。
- 页面出现“下载模板/批量导入”时，必须先下载系统模板，保持列名和工作表结构不变；导入失败行会返回行号和原因。
- “示例”数据用于说明字段填写方式。示例记录不能编辑或参与业务流转，系统管理员可以在列表页明确删除。

## 2. 首页与通知

### 2.1 总览

总览展示当前账号有权限访问的关键指标、待处理事项、近期动态、项目/需求概况和团队数据。ITSM 数据按服务请求、变更、事件、问题分别展示：每个面板保留本模块未关闭/处理中数量及 P1–P4 处理级别分布，并补充本模块的 SLA、审批、实施、已知错误或关闭率等指标，不再重复展示跨模块 ITSM 汇总。管理员可在界面与品牌配置中设置不同角色的默认首页。

### 2.2 通知

点击右上角铃铛查看站内通知。通知用于提示流程待处理、审批、开通申请、同步结果和系统事件。通知不会改变业务数据，必须进入对应单据完成实际处理。点击弹窗标题右侧的“一键已读”，可将当前账号所有未读通知一次性标记为已读；点击“清除已读”可清理当前账号已经读过的通知。清除采用软删除，不影响未读通知、源业务单据或审计记录。

## 3. ITSM

### 3.1 服务请求

**用途**：业务用户提交服务申请，IT 团队受理、处理并关闭。

**运作逻辑**：登记 → 流程分派 → IT 受理/处理 → 待用户确认 → 关闭 → 评价。IT 人员完成处理只进入 `resolved`，不代表用户已经确认；只有登记人本人能确认关闭，管理员不能代确认。用户选择“仍未解决”时，流程回到最近的实际处理节点并增加重开次数；IT 再次解决后，用户看到的是本轮最新有效处理说明。普通业务用户选择服务项后，系统读取当前发布表单，网页端和 Aily MCP 共用同一套字段校验。IT 内部人员和管理员可展开“内部处理信息”补充受理人和内部备注。

**操作步骤**：

1. 进入“ITSM → 服务请求”，点击新建，选择服务类别和具体服务项；业务用户只能选择其服务对象范围内、已上架且非示例的服务项。
2. 系统加载服务项已发布表单。填写标题、紧急程度和描述等核心字段，并只补充该表单要求的动态字段；服务项未发布表单时不能提交。
3. 提交前后端都会按已发布版本校验答案。提交成功后保存表单版本与定义快照、生成编号、启动服务项绑定流程，并按“服务项规则 → 目录规则 → 全局兜底”自动派单；没有合格处理人时进入人工队列，不会静默丢单。
4. 在列表中通过状态、当前节点和“待我处理”定位任务；打开详情完成处理说明，流程节点完成后系统自动推进状态。
5. IT 人员提交处理说明后，工单进入“已解决/待用户确认”。登记人在网页确认“同意”后关闭；选择“驳回”并填写原因则重新打开。关闭后可选择 1–5 星、最多 5 个标签并填写 500 字以内意见；结果保留在基本信息中并写审计。

**端到端流转**：提交服务项 → 按服务项/业务域分派 → 当前处理人处理 → 登记人验收 → 关闭并沉淀 SLA、审计和绩效取数。处理人不能直接修改终态；验收不通过会带理由回到处理节点。

**异常处理**：需要补充信息时在当前节点说明，不要通过修改字段绕过流程；若 SLA 即将超时，先在详情确认当前处理人和节点，再按权限重分派或升级。

### 3.2 服务目录

**用途**：维护可申请的 IT 服务目录及目录下的服务项。

**操作步骤**：

1. 左侧选择目录，右侧查看该目录的服务项；右侧标题旁的返回/前进按钮可在当前目录和全部服务项之间切换。
2. 使用搜索框查找服务项，使用“全部/上架中/已下架”筛选。
3. 点击表头可按编号、名称、类型、SLA、状态等排序。
4. 目录和服务项的操作区均提供上架、下架、编辑、删除（需权限）。删除目录时，系统会再次提示并可同时软删除该目录下的全部服务项；历史工单、项目和配置项记录不会被删除。左侧目录卡片显示上架中和已下架服务项数量。
5. 编辑或新建服务项时，在“服务对象”下拉菜单选择“全体员工”或“自定义范围”。选择自定义范围后，打开组织架构树，可勾选一个或多个部门、在岗员工；保存时系统会校验引用仍处于有效状态，并在列表中显示可读摘要。业务用户门户只展示其本人命中的服务对象范围，创建服务请求时后端也会再次校验；管理员和 IT 内部角色仍可查看完整目录。
6. 编辑服务项时同时维护搜索关键词、同义词、典型场景、排除场景、绑定流程和默认优先级；这些字段决定 Aily 通过 MCP 实时检索时的召回和预览信息。只有已上架、非示例且当前用户可申请的服务项会返回给普通用户。
7. 点击服务项操作区的“表单/派单”，使用可视化设计器新增字段、保存草稿并发布表单版本；P1 支持文本、长文本、单选、多选、数字、日期/日期时间、人员、部门和布尔项。已发布版本不可原地覆盖，历史工单继续保留创建时的答案和定义快照。同一窗口可配置固定人员、固定用户组、轮询或人工队列派单。
8. 批量维护服务项时下载模板、填写后导入；导入结果会区分成功和失败行。历史上以自由文本维护服务对象的服务项，首次编辑时需要重新选择结构化范围。

### 3.3 CMDB

**用途**：维护配置项及其与服务、人员、供应商的关联。

**操作步骤**：新建或编辑配置项 → 选择类型、所属服务和负责人 → 保存 → 在列表按关键字段搜索、筛选、排序。配置项删除和批量导入受管理员权限控制。

### 3.4 SLA

**用途**：定义服务请求的响应、解决时限和优先级策略。

**运作逻辑**：服务请求创建时按服务项和优先级匹配 SLA；系统记录首响、解决和超时状态，用于服务看板和绩效取数。

### 3.5 事件、变更与问题

三类单据均由流程驱动：

- **事件管理**：记录服务中断或异常，按影响和紧急度处理、恢复并复盘。
- **变更管理**：提交变更方案、风险和回退计划，审批通过后实施，最后验证和关闭。
- **问题管理**：分析重复事件根因，形成已知错误、永久修复和复盘结论。

进入详情后，右上角动作与流程图动作遵循同一套权限。审批节点可点击“同意”或“驳回”；驳回必须填写理由，同意理由可选。处理节点使用“完成此步骤”推进，知会节点只产生通知，不产生待办任务。

**当前已发布变更流程**：变更申请（范围、受影响服务/配置项、窗口、风险、验证标准、回退方案）由 `it_ops` 登记 → `it_op_leader` 审批（`it_bm` 知会）→ `it_ops` 实施与验证 → `is_mgr` 变更复盘（`cio` 知会）。审批通过前不能实施；状态机当前允许 `cio`、`it_tm`、`it_op_leader` 批准/拒绝，驳回必须填写理由；验证失败时先回退或关联事件，再关闭。流程中心已发布版本优先于代码种子，流程调整需另存新版本。

**事件与问题的衔接**：事件以恢复服务为目标，记录影响、紧急度、恢复动作和复盘；同类事件重复发生时可升级为问题，问题继续分析根因、已知错误和永久修复，修复验证通过后再关闭问题。

### 3.6 供应商管理、合同管理、知识库

- **供应商管理**：维护供应商基本信息、服务范围、联系人、评级和合作状态。
- **合同管理**：维护合同编号、供应商、金额、起止日期、续约提醒和附件。
- **知识库**：创建、编辑、发布和归档知识文章；文章可关联服务请求和解决方案。

三类页面均支持搜索、核心字段筛选、表头排序和分页；新增/编辑/删除按照角色权限控制。

## 4. 项目管理

### 4.1 项目列表与项目组合

“项目列表”管理项目生命周期，“项目组合”按组合查看项目范围、负责人、状态、健康度和进度。创建项目时，项目经理只能从数字化团队中选择。

### 4.2 项目操作流程

1. 点击新建项目，填写项目名称、项目经理、计划起止、预算、组合和项目描述。
2. 可通过章程导入上传 Word 文件，系统解析项目目标、范围、组织、里程碑和 WBS 草稿。
3. 在项目详情维护里程碑和 WBS 任务。WBS 支持 0%/50%/100% 预设，也支持填写 0–100% 的自定义比例。
4. 父级任务设为 100% 时，子任务自动变为 100%；子任务修改后，父级按直接子项平均值递归计算。
5. 项目进度按末级任务工期加权汇总，不直接按父级行数平均。
6. 项目流程包括立项启动、执行监控、收尾复盘等节点；项目经理、PMO、CIO 的处理权限由流程定义决定。

**项目交付闭环**：章程确认/立项 → 基线计划（里程碑、WBS、预算、风险） → 执行监控 → 变更决议（如范围、日期或预算变化） → 交付验收 → 收尾复盘。项目经理维护基线和收尾，任务负责人维护末级任务，PMO 监控交付质量；子任务未完成时不能直接关闭项目。

**WBS 进度规则**：编号层级代表父子关系；父级设置 100% 会级联所有后代，子级变化后父级按直接子项平均值递归汇总，项目总进度再按末级任务计划工期加权。只有完整工作包完成时才应直接把父级设为 100%。

WBS 表格支持冻结表头和左侧前三列、拖动调整列宽/行高、底部横向滚动条。布局调整保存在当前浏览器中。

## 5. 需求管理

### 5.1 需求总览

业务用户可以登记需求，IT 团队负责澄清、评审、方案评估和路由。需求列表可按状态、业务域、MoSCoW、决议和负责人筛选。

登记前必须由管理员至少配置一个已启用的业务域；网页和 Aily MCP 都只能从该真实列表选择，不能由 Aily 自行编造。若列表为空，MCP 会返回“当前没有已启用的业务域”的阻塞原因，管理员应先在“系统管理 → 组织管理 → 业务服务域”完成配置。

**典型流程**：登记 → 需求评审 → 方案评估 → 转开发/转项目/暂缓/拒绝 → 验收。每个节点的处理人和知会人由流程配置决定。

**节点职责**：业务申请人定义问题价值和验收标准；IT BP/专业线负责人负责澄清、依赖和可行性评估；评审/审批节点必须产生同意或驳回决定；通过后才路由到开发任务或项目，交付完成并由业务负责人验收后关闭。评论内容不能替代审批结果。

### 5.2 任务跟踪

查看需求拆分后的任务、当前处理人、计划日期、完成状态和逾期情况。处于“实现中”的需求负责人可以在需求详情或任务跟踪页连续登记多条任务，并维护任务说明、负责人、计划日期及计划/实际工时；处理人只能更新自己任务的状态和实际工时。任务状态会反映到需求整体进度，删除任务仍需要需求管理/任务跟踪编辑权限。页面按钮只反映当前能力，服务端会再次校验权限，因此已有任务和需求数据不会因页面升级而被覆盖。

### 5.3 任务管理

从左侧“任务管理”进入：开发任务页的两个标签分别是“需求开发”和“Bug 修复”，委派任务是独立页面。旧的“任务跟踪”书签会自动进入“开发任务 → 需求开发”，不会丢失原需求任务。

任务管理下的“开发任务”包含“需求开发”和“Bug 修复”两个标签；“需求开发”展示原需求分解任务，“Bug 修复”按登记、产品经理确认、开发负责人生成多条修复/测试任务、开发执行、产品经理验证关闭的流程处理。普通 IT 用户可以登记 Bug，只有所属系统产品经理可以确认和验证，开发人员只能维护分派给自己的执行字段。

“委派任务”用于记录工单、问题、事件、技术研究和其他非项目级工作，状态为“登记→排期→执行→关闭”，并可暂停或中止。登记且未分配的任务由登记人删除；任务分配后至关闭前只有管理员可以删除。列表页的编辑、暂停、中止、关闭按钮以服务端返回的能力字段为准，服务端仍会再次校验。

### 5.4 评分规则

管理员配置需求评分维度、权重和分段标准；评审人按规则对需求进行评分。评分规则修改会影响后续评审，不会覆盖已完成的审计记录。

## 6. 团队管理

### 6.1 团队总览

查看数字化团队在岗人数、培训活动、专项活动、招聘需求、工单/项目/需求负载和积分排行。面板可按当前账号自定义显示板块。

### 6.2 人效评分

人效评分按考核周期运行，默认由角色贡献 80% 和团队贡献 20% 组成。

- **总览**：查看当前矩阵角色周期结果：角色职责结果 80%、团队贡献 20%、加减分和当前总分。展开员工行可查看各角色、权重、系统参考分、负责人初评、CIO 终审和当前生效分；这里不再显示旧版岗位“默认方案”。
- **计分规则**：只查看和维护岗位角色档案、评价维度、维度权重、系统取数口径及流程/RACI 节点映射；CIO/系统管理员不在此页调整团队活动积分。当前模型没有全局默认方案；点击“新增角色规则”创建一套可复用的角色职责规则，再到周期员工详情分配角色和权重。
- **活动积分 → 积分规则**：查看和维护团队贡献活动的事件分值、启停状态、六个贡献维度的权重/目标积分以及内外部满意度组合比例；修改仅影响后续事件与考核周期。
- **分级评审**：每名员工在当前页面汇总为一行，进入“评分明细”后维护角色权重、评审人、评审人权重、各维度评分和证据。多个评审人的分数按配置权重汇总。
- **外部原数据**：只允许录入 `external_business_satisfaction`，评价对象必须是业务服务域，原始分按 0–100 百分比录入；系统按内外部满意度配置比例换算。外部评分只作用于该业务域负责人、备份负责人和 IT BP。
- **我的最终结果**：员工只能查看发布后的个人结果；未发布周期的中间评分不会对普通员工开放。

IT PMO 角色自身由 CIO 直接评价；IT PMO 作为项目经理虚拟团队负责人，可对 IT 项目经理进行初评。负责人评审、CIO 终审、发布和锁定均留有审计记录。

### 6.3 岗位编制

包含“岗位定义”和“招聘需求”两个标签页。

1. 岗位定义：维护岗位编码、岗位族、职责、编制数、正式在岗、服务业务域、主责角色、技能和职级框架。
2. 招聘需求：选择岗位，填写招聘人数、级别、任职资格、状态和进度备注。
3. 系统管理员和 CIO 可以在清单页直接编辑字段，也可以打开详情页编辑；支持删除、导出 Excel、下载模板和批量导入。
4. 导入必须使用系统最新模板，岗位编码和招聘需求的关联字段不能改名。

### 6.4 学习成长

页面包含“培训提升”和“学习任务”两个同级标签页：

- **培训提升**：登记培训/分享活动，选择主讲人和参与人，填写日期、主题和产出链接；系统按活动积分规则自动计分。
- **学习任务**：员工填写本考核周期学习成长目标、目标说明、完成进度、佐证和补充说明；进度按 0–100% 计算并换算为团队贡献积分。记录支持编辑和删除，保存后会重新计算当前周期积分。

### 6.5 活动积分与团队文化

- **活动积分**：维护专项活动、建议改善、知识资产和跨团队支持等积分事项；积分规则可配置，记录进入团队贡献计算。
- **团队文化**：维护愿景、年度目标和行为准则。管理员/负责人编辑后保存，所有成员可查看最新版本。

## 7. 流程中心

### 7.1 流程定义

管理员或 CIO 配置六类业务单据的流程版本、节点顺序、处理节点/审批节点、处理人、知会人、角色和自动化等级。发布后新建单据使用新版本，存量单据继续使用创建时的流程快照。

### 7.2 流程监控

按单据类型、状态、当前节点、处理人和时间查看运行中的流程。点击单据进入详情处理；未指派节点可由具备权限的人员认领，处理完成会自动推进状态并触发通知。

## 8. 系统管理

### 8.1 组织管理

- **组织架构**：查看/维护部门树和人员主数据；飞书同步后，管理员在此配置数字化团队范围。范围等于所选部门成员与“单独指定人员”的并集；对于 Test 等包含多家供应商的混合组织，只选择需要参与 IT 工作和绩效考核的外包人员即可，不会纳入其同部门其他人员。
- **业务服务域**：从组织架构选择服务部门，可选择覆盖下级部门；负责人、备份负责人和服务团队只从数字化团队中选择。

### 8.2 用户与组管理

- 用户页管理登录账号、关联人员、角色、用户组、状态、初始密码和登录开通。“关联人员”从完整公司组织人员中选择，并显示姓名与部门，不受数字化 IT 团队范围限制。编辑账号时可重新绑定或清空后保存；清空只解除账号绑定，不删除人员档案、部门归属、用户组成员关系或历史记录。
- 用户组是纵向专业资源池，可配置负责人（TM）、成员和授予角色。
- 飞书登录申请在“登录开通”标签页审批；批准、驳回、查看密码、邮件发送均留审计。

### 8.3 角色与权限

- **角色定义**：维护内置角色名称/说明和自定义角色。
- **预分配规则**：按部门类型或具体部门设置新用户默认角色。
- **权限配置**：按模块设置查看、新建、编辑、删除权限。admin 默认拥有全部权限，审计员只读。

### 8.4 数据字典与状态机配置

数据字典维护分类、编码和值；状态机配置维护状态、颜色和允许流转。状态删除前必须确认没有存量单据正在使用。

### 8.5 系统集成

系统集成包含飞书、邮件服务器和 AD/LDAP 三个标签页：

- 飞书：配置自建应用凭证、扫码登录、组织同步范围、自动同步开关和频率；这些能力用于登录和组织身份，不再配置或订阅飞书服务台。Aily 智能体与 ITOM 的业务调用统一通过 MCP Server。
- 公网入口：在“Aily Agent + MCP Server”区域填写“公网访问根地址（域名/IP + 服务端口）”，当前 IDC 地址为 `https://itom.snnc.cc:30443`。这里填写外网实际访问入口，不要填写 `/mcp/` 或回调路径；保存后页面会自动生成 MCP 地址、飞书登录回调和卡片回调地址，三者使用同一域名和端口。清空该字段后不会继续显示可复制的公网地址。正式环境的 HTTPS 证书必须由公网受信 CA 签发、匹配域名且证书链完整。
- Aily + MCP 身份与权限：Aily 调用 `/mcp/` 时携带服务端签发的 JWT；ITOM 校验签名、有效期、租户、Agent 和来源后，将飞书用户映射到已启用的 ITOM 账号。未映射身份、越权服务项或缺少模块权限的调用会被拒绝，MCP 不直接写数据库或绕过流程。
- P1 用户入口：Aily 可实时搜索当前用户可申请的服务项、读取已发布表单、生成脱敏预览和一次性确认令牌；用户明确确认后才幂等创建 `service_request`。新系统、新功能等诉求使用独立的 IT 需求表单和需求管理流程，不会伪装成服务请求。普通用户不能通过 Aily 创建 IT 事件、变更或问题。
- P2 服务闭环：Aily 可列出本人所有待确认服务请求；存在多张时必须让用户按工单编号选择，不能猜“最近一张”。用户明确选择已解决后关闭，选择仍未解决并说明原因后重开；关闭后可提交 1–5 星、标签和意见。受理、解决、重开、关闭和评价通知来自 ITOM 可靠发件箱，内部备注、根因和审批意见不会发给 Aily。管理员在系统集成中配置机器人凭据、卡片回调 Verification Token 与 Encrypt Key，并在飞书开放平台只订阅新版“卡片回传交互（`card.action.trigger`）”后，解决/提醒通知提供“已解决并关闭、仍未解决”按钮，关单通知提供 1–5 星按钮；未就绪时仍发送纯文本。点击“仍未解决”后在原卡片填写必填原因再提交。普通对话仍走 Aily + MCP；按钮由 ITOM 验证飞书签名和点击人身份后执行同一领域校验。
- 环境边界：IDC Kubernetes 是唯一运行、联调和验收环境，当前正式公网根地址为 `https://itom.snnc.cc:30443`。默认不得在本地启动 ITOM、数据库、Docker Compose、8180 或 ngrok；只有管理员明确批准临时隔离排障时才允许例外，且结果不作为正式验收。不能向飞书填写 localhost 或内网地址；Aily 自定义 MCP 必须使用页面生成的带末尾斜杠 `/mcp/`，卡片回调使用 `/api/integrations/feishu/card-actions`。不要把密钥放入 URL、聊天提示、日志或截图；公网根地址变化后需重新保存并同步 Aily、飞书 OAuth 与卡片回调配置。
- 邮件服务器：配置 SMTP，用于管理员手工发送初始密码及后续系统通知。
- AD/LDAP：配置目录服务器、搜索基准、绑定账号和认证方式。

### 8.6 界面与品牌

管理员可以配置登录页名称、简介、横版/方形 Logo、Favicon、主题、密度、侧栏风格、角色默认首页、公告和环境标识。图片上传后先裁剪、缩放、旋转，确认裁剪区域后才保存。

### 8.7 审计日志

按实体类型、动作、操作人和时间查询关键变更。登录、权限、流程、评分、外部原数据、用户密码和品牌发布等操作均应通过审计日志追溯。

### 8.8 活动积分规则（入口：团队管理 → 活动积分）

进入“团队管理 → 活动积分 → 积分规则”查看团队贡献活动的自动事件积分规则。系统管理员和 CIO 可以编辑分值、启停状态、维度目标和满意度组合比例，其他角色只能查看。岗位职责结果的规则进入“团队管理 → 人效评分 → 计分规则”维护，不能与活动积分混用。

- 修改只影响后续新产生的自动积分事件；已经写入积分台账的历史记录不会自动重算。
- 停用规则后，对应事件仍可发生，但不会新增该条积分流水；重新启用后恢复计分。
- 每次修改都会记录积分规则编码、修改前后分值、启停状态、操作人和时间。
- 规则的 `计分归属` 由系统强制隔离：活动积分接口只返回 `team_contribution`，岗位结果事件不会出现在活动积分页；角色绩效页面按角色职责取数，避免重复计分。

## 9. 个人中心

个人中心提供基本信息、安全设置、通知偏好、操作记录、飞书绑定和界面偏好：

1. 在“界面偏好”选择浅色、深色或跟随系统，并设置默认/紧凑内容密度。
2. 在“安全设置”修改密码；修改后管理员保存的初始密码密文会被清除。
3. 在“操作记录”查看本人行为，不可查看其他人的审计详情。

## 10. 常见问题与排查顺序

### 看不到菜单或人员

先确认账号角色和模块权限，再确认人员是否属于管理员配置的数字化团队范围（所选部门成员或单独指定人员）。重新登录可刷新权限和组织同步结果。

### 流程按钮不可用

检查当前节点是否由本人处理、是否已被他人认领、单据是否已经进入审批/终态，以及当前流程版本是否允许该动作。

### 导入报错

重新下载最新模板；不要修改工作表名称、列名和隐藏校验列。根据返回的工作表、行号和错误原因修正后重新导入。

### 评分结果没有变化

确认当前周期是否已重新取数，外部满意度是否按业务服务域录入，学习任务是否保存，规则是否已经发布。已发布周期需要生成新版本，不能直接覆盖。

### 需要反馈问题

反馈时请附：页面路径、账号角色、操作步骤、发生时间、错误提示、单据编号/周期和截图。不要在工单或聊天中发送密码、Token 或 SMTP 密钥。
