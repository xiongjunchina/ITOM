# DMC 与数字化项目立项制度—ITOM 适配映射

- 状态：已确认，待按 `feature-local` 实施
- 日期：2026-09-01
- 适用范围：ITOM 需求、项目、统一投入、报表、权限与审计能力
- 权威制度：
  - `数字化管理委员会（DMC）运作机制（试行）_20260901.docx`
  - `数字化项目立项决策机制（试行）_20260901.docx`

## 1. 结论

两份制度与 ITOM 的产品定位总体兼容。ITOM 继续作为“需求与项目治理的管理中枢”，不承接 DMC 会议、财务预算、采购合同、法务/安全审批、业务流程设计或数据治理等专业系统的完整职能。

制度文件明确的五个需求评估维度与已确认的目标模型一致：

1. 战略对齐
2. 业务价值
3. 技术可行性
4. 业务成熟度（组织、人员、流程）
5. 风险等级

现行代码仍保留 D6“价值速度”和 D4“组织就绪度”命名，因此需要做兼容性收敛；历史评分不删除、不重算、不在普通页面展示版本变化。

## 2. 制度事实与系统边界

| 制度要求 | ITOM 应承载的内容 | 不应由 ITOM 承载 |
|---|---|---|
| 年度计划与项目组合 | 项目来源、计划年度、组合引用、DMC授权快照 | 年度预算账和财务总账 |
| 计划外需求转项目 | 需求评估、项目化判定、决策结果、需求-项目关联 | 线下会议组织和专业评审过程 |
| DMC 决策 | 议题、结论、金额、预算来源、条件、责任人、期限、检查时间、依据引用 | 完整会议排期、在线表决和投票系统（首期） |
| 业务成熟度 | 组织、人员、流程成熟度说明及评分 | APQC/流程设计与流程执行事实 |
| 投资授权 | 外部投资口径及授权级别 | 采购、合同付款和财务核算 |
| 专业审批 | 外部审批状态、编号、链接、摘要和附件引用 | 法务、数据、安全、架构审批本身 |
| 项目生命周期 | 启动、预算待落实、执行、验收、观察、关闭和值得复盘记录 | 专业系统中的实施细节 |
| 管理报告 | DMC季度、半年度、年度和项目组合分析 | 专业系统的明细报表主数据 |

## 4. 目标数据与流程映射

### 4.1 需求评估

新需求评估字段使用五维模型。D4 的评分说明融合组织、人员和流程：

- 1分：无明确业务负责人，组织职责不清，流程不存在或无法描述；
- 2分：有局部负责人或局部流程，但跨部门职责和关键节点不清；
- 3分：组织职责和主流程基本明确，可形成实施范围，但仍需补齐细节；
- 4分：业务负责人、参与人员、流程节点、输入输出和例外处理基本明确；
- 5分：有明确业务负责人和资源承诺，流程已细化到可直接支撑系统设计、数据定义和验收。

制度要求计划外需求提交完整的需求说明，包括业务问题、预期结果、业务负责人、资源、边界/风险和业务成熟度。该要求属于**申请材料完整性**，不等同于强制 D1/D2 上传评分依据。D1/D2 依据、附件和管理决议仍按“可记录但不强制”的既定方案处理。

### 4.2 双轨项目治理

```text
年度计划项目：年度组合审议 → DMC批准即立项/投资授权 → 预算落实 → 启动

计划外需求：需求登记 → 五维评估 → 项目化判定 → 金额/影响判断
            → 数字化负责人或Eason/DMC决策 → 预算落实 → 项目启动
```

项目化判定至少覆盖：新建/替换系统、外部 IT 服务采购、内部工作量达到 20 人日、独立预算、独立详细计划或独立项目负责人。未达到项目标准的事项继续进入普通需求、运维工单或开发任务。

### 4.3 决策级别

默认配置与制度一致：

| 外部投资授权金额 | 决策级别 | ITOM记录 |
|---:|---|---|
| ≤ 30 万元 | 数字化团队评估、数字化负责人决定，报 DMC | 决策人、时间、结论、预算来源 |
| > 30 万且 ≤ 100 万元 | 数字化负责人评估、Eason决定；可要求DMC | 决策级别、升级原因、结论和条件 |
| > 100 万元 | DMC直接决策 | DMC议题、决议、签署人和检查安排 |

授权金额只统计软件、硬件、云、咨询和实施等外部投入。内部人力、沟通管理和上线后日常运维仍进入投入分析，但不混入投资授权金额。

### 4.4 生命周期与签署

ITOM需记录以下治理节点：预算待落实、项目启动、阶段验收、上线、观察期、价值评估、运维移交和关闭。观察期默认：外部投资大于 100 万元至少 3 个月，其他项目至少 1 个月。

年度计划项目和计划外项目使用不同的签署矩阵，但都保存签署人、角色、时间、结论和依据快照。外部专业审批只保存引用，不把专业审批状态复制成 ITOM 的自有事实。

## 5. 分阶段实施计划

### P0：制度适配最小闭环

1. 需求评分切换为五维，D4改名“业务成熟度”；保留旧字段用于历史只读。
2. 增加计划内/计划外项目来源和项目化判定清单。
3. 增加 30 万/100 万元决策阈值配置，禁止与人日阈值混用。
4. 增加 DMC 决策记录、升级原因、结论条件、责任人、期限和检查时间。
5. 需求转项目时保留需求、评估和决策快照。

### P1：项目治理和投入口径

1. 增加预算待落实、阶段验收、观察期、价值评估和运维移交。
2. 增加外部投资授权金额、全生命周期成本和内部人力估值的分离聚合。
3. 增加签署矩阵、外部审批引用和多阶段项目支持。
4. 扩展最小权限和治理审计事件。

### P2：报表和集成

1. 增加 DMC 季度治理、半年度复盘和年度组合报告模板。
2. 增加计划外需求转项目、决议逾期、预算偏差、观察期和价值兑现指标。
3. 对接财务、采购、流程、安全、数据等专业系统的只读引用或受控摘要。
4. 如未来确有需要，再单独评估 DMC 在线表决，不作为本轮前置条件。

| 历史评分不被改写 | 数据库迁移/读取测试和只读页面验证 |
| 年度与计划外项目双轨可区分 | 项目创建、需求转项目和筛选测试 |
