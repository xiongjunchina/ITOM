# ITOM 网页智能体设计基线

> 状态：**设计已确认；WA0 Task 1–6 已实现并完成 Task 6 Fix Round 3；Task 7+ 待实施**
> 确认日期：2026-08-01
> 中文为权威版本；英文镜像见 `docs/en/superpowers/specs/2026-08-01-itom-web-agent-design.md`。

## 1. 背景与目标

ITOM 的目标用户普遍缺少 ITIL 基础。普通业务用户不应先理解服务请求、事件、问题、变更、需求和项目的专业边界再使用系统；IT 员工也需要结合本人角色、当前页面和流程任务获得模块说明、记录查询与下一步指导。

本设计建设“ITOM 智能助手”，采用**双入口、统一能力内核**：飞书 Aily 保持现有普通用户 MCP 入口，ITOM 网页新增使用当前登录会话的对话入口；两者身份协议隔离，但复用 ITOM 领域服务、表单校验、权限、数据范围、流程、确认、幂等与审计。ITOM 始终是业务状态的唯一事实来源。

目标用户能力：

- 普通业务用户只围绕本人服务请求进行搜索、草稿、提交、查询、补充、确认/重开和评价；
- BDO 在普通业务能力上增加本人 IT 需求登记与跟进；
- IT 员工按有效角色、功能权限、数据范围和流程任务获得全系统指导与分阶段开放的操作能力；
- 管理员可以配置模型、智能体档案、知识范围和最高能力等级，但不能通过模型配置授予业务权限。

## 2. 不可突破的架构原则

1. **双入口、身份隔离**：网页使用 ITOM 登录身份；Aily 继续使用 `x-aily-jwt`、租户/Agent/Origin 白名单和外部身份映射。网页不直接调用公网 `/mcp/`。
2. **统一领域能力**：两种入口复用同一领域服务，不复制服务目录、表单、流程、状态或授权逻辑。
3. **模型不授权**：模型只做理解、整理、追问和编排；服务端每次能力调用重新计算权限、数据范围、记录状态和流程任务。
4. **模型不写表**：所有查询和变更必须经过注册能力与领域服务；不提供通用 SQL、HTTP、Shell、文件系统或任意数据库工具。
5. **写操作受控**：创建、修改、派单、流转、确认和关闭必须先形成服务端预览，再由用户明确确认并幂等执行。
6. **成功由服务端声明**：只有领域服务成功返回后，界面才可显示“已创建”“已关闭”等结果；模型文本不是业务结果。
7. **可降级**：现有确定性“创建单据指引”保留为模型不可用时的安全降级，不删除其规则资产。
8. **现有 Aily 边界不变**：不扩大普通用户 MCP 工具，不把 IT 员工网页能力自动暴露给 Aily。

## 3. 总体架构

```text
飞书 Aily ── x-aily-jwt ──▶ 现有 Aily MCP 适配器 ─┐
                                                     ├─▶ 统一智能体能力层
ITOM 网页 ── Bearer/登录会话 ─▶ 网页会话适配器 ───┘        │
                                                            ├─ 身份与策略上下文
                                                            ├─ 智能体编排器
                                                            ├─ 模型网关
                                                            ├─ 安全知识检索
                                                            └─ 能力注册中心
                                                                    │
                                                                    ▼
                                                      ITOM 领域服务 / RBAC /
                                                      数据范围 / 流程 / 审计
                                                                    │
                                                                    ▼
                                                               PostgreSQL
```

组件职责：

| 组件 | 负责 | 禁止 |
| --- | --- | --- |
| 网页会话适配器 | 登录身份、语言、白名单页面上下文、SSE 流式响应 | 接受前端自报角色/权限或整页 DOM |
| Aily MCP 适配器 | 保持现有 Aily 身份和普通用户工具契约 | 扩展成内部员工通用入口 |
| 智能体编排器 | 意图理解、追问、能力选择、结果组织 | 自行修改业务状态 |
| 模型网关 | 模型协议适配、流式输出、超时与主备切换 | 向前端或提示词暴露密钥 |
| 能力注册中心 | 权限、数据范围、输入输出、风险、确认和处理器 | 让模型自由拼接接口 |
| 安全知识检索 | 已发布模块定义、操作说明和用户可见业务知识 | 返回内部备注、密钥或未授权记录 |
| 领域服务 | 表单、状态、流程、权限、幂等、事务和落库 | 绕过既有业务规则 |

## 4. 用户能力边界

### 4.1 普通业务用户 `requester`

允许服务项搜索、真实表单、服务请求草稿/预览/明确确认提交、本人服务请求查询与补充、本人解决确认/重开及评价。禁止 IT 需求、事件、问题、变更、项目、Bug、内部任务和他人数据；不得返回内部备注、根因或审批信息。

### 4.2 BDO

继承普通业务能力，并可取得真实 IT 需求登记表单、准备/确认登记、查询和跟进本人需求。BDO 不因此获得需求评审、项目管理、流程监控或 IT 内部任务权限。

### 4.3 IT 员工

所有 IT 员工可获得本人有权访问模块的定义、字段、操作说明、单据类型推荐、本人待办、可见记录查询、状态/流程下一步解释、草稿和精确页面跳转。写能力仍按角色、权限、数据范围和当前流程处理人逐项开放；角色提示词只改变表达方式，不授予能力。

### 4.4 管理员

管理员拥有功能入口和模型治理能力，但仍受业务硬规则约束，例如不能代替服务请求提交人确认解决，不能通过提示词扩大普通用户范围，也不能读取或回显模型/集成密钥。

## 5. 能力风险等级

| 等级 | 类型 | 执行规则 |
| --- | --- | --- |
| L0 | 概念、字段、操作说明与导航 | 可直接响应 |
| L1 | 当前权限和数据范围内的查询 | 服务端鉴权后执行 |
| L2 | 类型推荐、补齐字段、草稿与预览 | 不写正式业务数据 |
| L3 | 创建、修改、派单、流转、确认、关闭 | 服务端预览 + 用户明确确认 + 幂等执行 |
| L4 | 删除、批量变更、角色权限、流程定义、密钥 | 首期不开放给智能体 |

管理员可为智能体档案设置最高风险等级和关闭能力，但只能收紧，不能突破用户权限。

## 6. 能力注册契约

每项能力由服务端代码注册，至少定义：`capability_code`、中英文说明、适用渠道/受众、功能权限、数据范围检查器、允许状态、输入 JSON Schema、结构化输出、风险等级、确认策略、幂等策略、领域处理器、审计策略、超时和降级策略。L3 处理器必须分别实现预览前记录授权 `authorize_preview`、只读 `preview` 和确认锁内 `authorize_record`；任一缺失都不得注册。

模型只接收本次用户可见的能力清单。能力定义优先保存在代码中，数据库配置只能关闭已注册能力，不能创建新的可执行处理器。

## 7. 网页体验

- 业务门户和内部工作台右下角均显示“ITOM 智能助手”入口；桌面端使用 440–520px 右侧抽屉，窄屏切换全屏。
- 页面只传递白名单上下文：路由、页面类型、当前实体类型/ID、当前标签和用户主动选中记录；不读取整页 DOM。
- 回复支持说明、规则来源、下一步建议、页面跳转、查询结果、缺失字段、预览和确认卡片。
- 用户始终可退出对话并使用原生页面；智能体故障不阻断核心业务。
- 原顶部“创建单据指引”在网页智能体成熟后合并到新入口，确定性规则继续作为降级能力。

## 8. 模型与智能体治理

系统管理新增“AI 智能体”页面，独立于 `aily_integration_config`。管理员可维护提供商类型、API Base URL、模型、加密 API Key、超时、最大输出、温度、流式/工具/结构化输出能力、主备模型和启用状态。第一版优先支持 OpenAI-compatible 适配器，其他协议通过适配器扩展。

保存或发布前必须探测连通性、鉴权、流式输出、JSON Schema、工具调用、超时和敏感数据回显。不支持工具/结构化输出的模型只能用于 L0/L1。管理探测采用“短事务锁内配置修订快照 → 无数据库事务的异步网络探测 → 短事务锁内修订比对与原子落库”，配置变化或删除后旧结果必须丢弃。

预置业务用户、BDO、IT 员工、管理员四类智能体档案；档案保存中英文系统指令、最高能力等级、已启用能力、知识范围和回复风格，采用草稿、测试、发布、版本和回滚。新版本必须保存带 schema 标记的完整活动配置快照；无法证明完整历史设置的 legacy 版本不得回滚，也不得由当前活动设置补齐。档案只能限制能力，不能授权。

## 9. 目标数据模型

| 表 | 用途 |
| --- | --- |
| `ai_provider_config` | 模型连接、加密密钥、能力探测、主备与启用状态 |
| `ai_agent_profile` | 受众档案、当前发布版本和最高能力等级 |
| `ai_agent_profile_version` | 版本化指令、能力/知识配置、发布与回滚 |
| `ai_conversation` | 网页会话、用户、语言、白名单页面上下文和生命周期 |
| `ai_message` | 脱敏消息、结构化内容、模型用量和耗时 |
| `ai_action` | 能力调用、风险、安全参数摘要、单次确认状态、命名幂等唯一约束、结果与业务实体 |
| `ai_provider_call` | 模型、Token、耗时、结果码和脱敏错误元数据 |

迁移只新增表、列、索引和默认权限，不改写现有业务数据、流程实例、`AilyIntegrationConfig` 或 `/mcp/` 契约。新功能默认关闭，完成模型测试和档案发布后再启用。

## 10. 对话保留与隐私

网页对话默认保存 30 天，管理员可在 0–90 天内调整；用户只查看本人对话。管理员默认查看运行指标和操作审计，不直接浏览完整对话。普通对话可按策略删除/归档，实际业务动作审计按系统审计策略保留。密码、Token、Secret、Cookie、授权头和敏感表单字段不得进入模型、消息表或普通日志。

## 12. 安全、确认与降级

- 每次调用重新检查活动账号、有效角色、权限、数据范围、记录状态和流程任务；
- L3 预览授权先于记录元数据，并在独立且最终回滚/关闭的 Session 执行；PostgreSQL 事务只读，处理器仅看到独立 Session 中重新加载的不可变 actor context 与无 Session-like 属性的 `ReadOnlyActionData` 门面。该门面只接受显式、有界的 SQLAlchemy `Select` 标量投影，返回递归冻结的 `FrozenActionRecord`，统一拒绝实体/关系结果、eager 结果、所有行锁、text/DML、过大 offset 与超限读取；写入、DML/text 事务语句、bind/get_bind/connection/begin/get_transaction/scalar/scalars、flush、commit、rollback 均失败关闭，预览状态必须精确为 `prepared`；
- 规范化输入若会被递归脱敏改变则整体拒绝；不得持久化/执行脱敏替代值，也不得以其计算幂等摘要；
- L3 确认凭证绑定用户、会话、能力、规范化参数摘要和有效期，单次使用；
- 重试使用命名唯一约束下的幂等键；同键同参只返回赢家且不重发 Token，同键异参拒绝；状态已变化时重新预览；
- prepare 存在两条顺序化路径：已有 key 先无锁探测，再按 `AiAction → active 会话` 顺序锁定/重检并比较摘要；新动作则在 preview 后先锁定并刷新所属会话，再无锁复查同 key，只有仍不存在才插入；命名唯一约束竞态会整笔 rollback 后以同样的 `AiAction → active 会话` 顺序恢复赢家。确认保持动作行锁后再锁定并刷新所属会话行，随后按模型治理锁序证明会话捕获档案/版本/提供商仍可运行；`authorize_record` 和 mutation 只获得不可变 actor context、`ActionUnitOfWork.lock_one()/update_locked()`、`FrozenActionRecord` 快照和不暴露真实 ORM 身份的 `LockedActionRecord`；领域写入、成功结果和审计位于嵌套 savepoint，失败只回滚 savepoint 并由同一外层事务提交有界终态；会话归档同样先锁定并刷新所属行再提交。处理器代码是受信任的进程内扩展代码，不是针对恶意 introspection/import hack 的沙箱；
- 用户输入、知识内容和记录正文均是不可信数据，不能覆盖系统指令或能力边界；
- 模型服务地址须在管理员允许范围内并使用 HTTPS；日志不得保存凭据或完整敏感答案；
- 模型不可用时回退规则指引、搜索和原生页面；非法结构、超时或流式断开不得触发写操作；

SQLite 自动化只证明服务调用顺序、回滚结果、竞态注入和 savepoint 语义。Task 9 IDC 必须补充真实 PostgreSQL 双 Session 证据：预览事务只读且写入失败；同/异载荷准备竞态只有一个赢家；确认 handler/审计失败后等待者读到 `failed` 且 handler 只执行一次；失败状态提交故障不被报告为已持久化。
- 主模型失败时仅在相同数据策略下切换备用模型，否则安全降级。

## 13. 分阶段实施

为避免与 Aily P0–P3 混淆，网页智能体使用 `WA` 编号：

| 阶段 | 范围 | 关键验收 |
| --- | --- | --- |
| WA0 | 模型配置/探测、档案版本、会话/消息/动作/调用审计、注册中心、脱敏与 SSE | 功能默认关闭；密钥不回显；历史业务数据不变 |
| WA1 | L0/L1 只读顾问、页面说明、单据判断、导航、本人记录/待办/下一步、规则降级 | 各角色只看到真实授权能力；模型故障不影响原生页面 |
| WA2 | 普通用户服务请求草稿/提交/查询/确认/评价；BDO 需求草稿/登记/查询 | 复用现有领域服务；普通用户不能登记需求/事件；Aily 回归不变 |
| WA3 | IT 员工高频 L3：关联建单、受理/派单/处理/流转、Bug 与任务 | 每次写操作预览确认；状态/RBAC/流程/幂等/审计均生效 |
| WA4 | 效果、成本、时延、失败率、场景测试、模型对比、知识治理 | 可量化评估且不以模型指标替代业务 UAT |

## 14. 验收与非目标

自动化必须覆盖 requester、BDO、IT 各角色和 admin，直接/组授予/继承角色，能力发现隔离、数据范围、L3 确认/过期/重复/冲突、提示注入、模型故障、脱敏、保留策略及现有 Aily MCP 全量回归。IDC UAT 必须证明普通用户仅服务请求、BDO 仅增加本人需求、IT 角色能力不同、权限修改即时收敛、模型发布/回滚可控、规则降级可用、动作审计可追溯，且现有 Aily 闭环不受影响。

本设计不包含飞书审批 P3、通用智能体市场、多智能体自治、模型审批、自由 SQL/HTTP/Shell、批量删除或以模型替代流程引擎；也不向普通业务用户开放事件、问题、变更和项目创建。
