## 1. 产品概述

### 1.1 产品定位

New_AOM 是一套面向 IT 团队的**轻量运营管理平台**，覆盖六个域：总览、ITSM 服务管理、项目管理、需求管理、流程引擎、团队管理。

### 1.2 设计原则（全系统强制约束）

1. **极简录入**：任何创建表单必填项 ≤ 8（实际全部做到 ≤ 5）；进阶字段默认折叠；与生命周期后期相关的字段在对应阶段才出现。
2. **派生数据零录入**：一切可计算的数据（编号、SLA、进度、健康度、成本汇总、积分、排行、达成率）由系统自动生成，页面上没有录入入口。
3. **渐进披露**：表单只在需要时展开（如工单选"变更"类型才出现变更字段）。
4. **事件驱动**：关键动作统一产生领域事件，驱动通知（预留飞书）与积分。
5. **无预计算表**：所有统计实时聚合，不维护任何月度统计/快照表

### 1.3 不做什么（明确排除）

- 组合治理独立域（阶段门/收益实现/能力地图/路线图）——组合仅作为项目的分组标签
- 数据治理域、组织成熟度评估、OCM
- ITSM 持续改进（CSI）、知识评审流、CAB 独立评审装置、ISO27001 安全事件字段
- 需求的版本快照、多人审批流、调研会话、三维打分
- 项目的干系人矩阵、基线管理、质量指标页、完整 EVM 录入
- AI Agent 注册/编排/升级装置、n8n 外部工作流引擎（流程能力内置实现，事件出口预留挂接点，见第 8 章）、初期的飞书集成（架构预留）
- 数据迁移（空库启动）

## 2. 用户与权限

### 2.1 角色（v1.0 初版定义，最新定稿见 2.1a：12 个内置角色，manager 已移除）

| 角色 | 说明 | 典型用户 |
| --- | --- | --- |
| admin 系统管理员 | 全部功能 + 系统配置（用户、状态机、SLA 策略、积分规则、流程定义） | 平台负责人 |
| it_pdm IT 产品经理 | 团队成员基础权限；侧重需求域：需求分析/排期/验收/关闭 | 产品经理/BA |
| it_pm IT 项目经理 | 团队成员基础权限；侧重项目域：项目创建与管理、WBS/里程碑/风险/成本维护 | 项目经理 |
| it_dev IT 开发 | 团队成员基础权限；侧重交付：需求开发任务、WBS 任务、工单处理 | 开发工程师 |
| it_ops IT 运维 | 团队成员基础权限；侧重运维：工单/变更实施/问题分析、CMDB 与 SLA 维护 | 运维工程师 |
| is_mgr 信息安全管理员 | 团队成员基础权限；侧重安全治理：安全类工单/问题处置、安全类 CI 维护、变更风险评估意见、审计日志查看 | 安全管理员 |
| it_bp IT 业务合作伙伴 | 团队成员基础权限；侧重业务接口：需求登记与业务对齐、代业务部门提单、验收协同、满意度跟进 | IT BP |
| requester 业务用户 | 提交工单和需求、查询自己提交的单据、评价满意度 | 业务部门同事 |

> it_pdm / it_pm / it_dev / it_ops / is_mgr / it_bp 六个岗位角色统称"团队成员"，基础权限一致（处理指派给自己的单据、录入知识/培训/建言、查看 Dashboard 与自己的积分），差异体现在两处：**流程引擎步骤的默认指派角色**（见第 8 章）和登录后的默认菜单侧重。一人可兼多角色（如既是 it_dev 又是 it_tm）。角色代码注意：`it_pdm` 为产品经理，`it_pm` 为项目经理。

### 2.1a 矩阵式组织角色（M3.6，2026-07-11 增补，详见 docs/06 §六/§七）

- 内置角色定稿 **12 个**：新增 `cio`（IT 总负责人）、`it_bm`（IT 业务线负责人，横向服务线）、`it_tm`（IT 专业线负责人，纵向资源池）；`manager` 已移除（2026-07-11，无存在必要）。预置流程按 ITIL 对齐重配（docs/06 §九）：变更审批=cio/it_tm、风险评估=is_mgr、复盘=it_tm、服务请求用户确认=it_bp。**内置角色名称/描述可编辑**（代码/继承/删除锁定）。
- **功能权限矩阵**：30 模块 × 4 动作（可见/新建/修改/删除）按角色配置（系统管理→权限配置页）；admin 隐式全权不可配；自定义角色创建时复制模板角色矩阵。三层权限分工：功能矩阵管页面开关、数据范围规则代码内置、流程权限在状态机/流程定义页。
- 业务域=横向服务线：负责人（BM）+ 服务团队成员；用户组=纵向专业线资源池：负责人（TM）+ 组授予角色。

### 2.2 自定义角色与用户组（2026-07-10 增补，M3.5 扩展）

- **内置角色**（上表 9 个 + auditor 审计员共 10 个）：承载系统功能权限，只读不可删改。auditor = 全模块只读 + 审计日志查看，不能修改任何单据（仅持有 auditor 的用户受全局只读限制；auditor+其他角色不受限）。
- **自定义角色**：admin 可创建，必须**继承一个内置角色**（获得其系统权限，不允许继承 admin），同时可被状态机流转规则和流程步骤精确引用（如自定义"DBA"继承 it_ops，变更审批仅限 DBA）。被用户持有或被流程/状态机引用的角色不可删除。
- **用户组**：团队/派单单位（如"数据库组"），**可授予角色——人进组自动继承组的角色**（对齐 ServiceNow"角色挂组"最佳实践；admin 不允许经组授予）；同时用作流程步骤默认指派对象和状态机流转的授权对象（引用键格式 `group:组码`）。被引用的组不可删除。
- **有效角色 = 直接角色 ∪ 组授予角色 ∪ 自定义角色继承**；用户永远可持有多个角色，任何规则都不得将用户绑死在单一角色上。

### 2.2a 身份与组织（M3.5，详见 docs/06）

- **部门**：公司组织架构（一人一部门，树形，类型 it/business/audit），纯数据不带权限；当前手工维护，上线前切换飞书/AD 同步（external_id 预留）。
- **账号开通（JIT）**：多认证源适配器（local 已实现；ad/feishu/sms/wechat 预留），认证成功自动建账号+人员档案；**开通规则**（按部门类型或具体部门→默认角色）仅首次生效，之后角色自由增减。
- **业务域/服务线**：编码/名称/负责人（BP）/备份负责人——负责人是字段不是角色。

### 2.3 权限要点

- 登录后按角色渲染菜单；接口层同步校验（前端隐藏 ≠ 权限）。
- 流程引擎的步骤默认指派可引用：内置角色、自定义角色（含继承匹配）、用户组，如：需求登记/业务对齐→it_bp、需求分析→it_pdm、项目节点→it_pm、变更实施→it_ops、需求开发任务→it_dev、变更风险评估→is_mgr。
- 状态机每条流转规则可限定允许的角色/用户组（留空=不限）。
- 人效评分明细仅 cio/it_tm/admin 可见（权限矩阵可调）；成员可见自己的积分流水与排行榜。
- 审计：所有写操作记录审计日志（操作人/时间/实体/动作/变更摘要）；admin 与 is_mgr 可查。

## 3. 全局约定

### 3.1 单据编号与主键

- 所有实体主键为 26 位 GLID（系统生成）。
- 业务编号自动生成，规则：`前缀-年月-序号`，如 `TK-202607-0012`（工单）、`PJ-202607-003`（项目）、`RQ-202607-021`（需求）、`PB/KB/ID` 等。用户永远不手填编号。

### 3.2 状态机

每类单据的状态流转由状态机配置驱动（admin 可调整），非法跳转被后端拒绝。各实体默认状态机见对应章节。

### 3.3 通知（预留飞书）

- 统一事件出口：工单创建/指派/SLA 临期/升级、变更待审批、里程碑逾期、需求阶段流转、建言被采纳等事件写入通知发件箱。
- 初期仅实现**站内通知**（顶栏铃铛 + Dashboard 告警区）；后续增加飞书通道适配器即可接入，业务功能零改动。

### 3.4 页面清单（约 22 页，对照旧系统 62 页）

登录、总览、工单列表/详情、服务目录、CMDB、问题、供应商、合同、知识库、项目管理（项目列表/项目组合两个标签页）、项目详情、需求列表/详情、流程定义、流程监控、团队总览、人效评分、岗位编制、培训发展、建言献策、团队文化、系统管理。

## 5. 域二：ITSM 服务管理

### 5.1 工单（核心，单表多类型）

工单类型：**事件 incident / 服务请求 service_request / 变更 change**。问题是独立实体（5.2）。

#### 创建表单

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 标题 | ✔ | |
| 类型 | ✔ | 三选一，默认"服务请求" |
| 优先级 | ✔ | P1 紧急 / P2 高 / P3 中 / P4 低，默认 P3 |
| 描述 | ✔ | 富文本 |
| 服务项 | ✔ | 下拉（来自服务目录）；带出服务线与 SLA 目标 |
| 受理人 | 可选 | 不填则按流程默认指派 |
| 关联 CI | 可选 | 折叠在"更多" |
| 备注 | 可选 | 折叠在"更多" |

选择"变更"类型时追加展开：变更类型（标准/普通/紧急）、风险等级、变更原因、回退方案、变更窗口（计划开始/结束）、实施方案（可选）。

#### 自动化（用户不填）

编号、状态、提交人及部门（当前登录人带出，可代提）、四个时间戳（提交/首次响应/解决/关闭）、SLA 目标（按服务项策略匹配）、实际响应/解决时长、SLA 是否达成、是否一次解决（按重开推断）。

#### 生命周期与状态机

```text
事件/服务请求：新建 → 处理中 → 已解决 → 已关闭
                ↘ 挂起 ⇄ 处理中          ↘ 重开 → 处理中
变更：新建 → 待审批 → 已批准 → 实施中 → 已解决 → 已关闭
              ↘ 已拒绝(终态)                ↘ 已回退 → 已关闭
```

- **解决时**填写：解决方案（必填）、根因（可选）。
- **关闭时**填写：关闭代码（下拉）。关闭后向提交人发起满意度评价（1-5 星，可选）。
- 变更审批：cio/it_tm（状态机可改）在待审批状态一键批准/拒绝（附意见），记录审批人与时间。
- 升级：P1/P2 工单超 SLA 目标 80% 未解决时产生升级通知。

#### 验收标准

- [ ] 服务请求从打开表单到提交 ≤ 30 秒（5 个必填项）
- [ ] 变更工单不经审批无法进入实施中
- [ ] SLA 达成自动判定正确（含挂起时间扣除）
- [ ] 工单解决自动产生积分事件

### 5.2 问题管理

来源：手工创建、工单升级转入（一键，自动带描述与关联）、需求关闭时遗留问题转入。

- 创建 3 必填：标题/描述/优先级；可选关联服务项。
- 阶段填写：根因、临时规避方案。
- 状态机：`新建 → 分析中 → 已知错误 → 已解决 → 已关闭`。
- 列表展示关联工单数（同根因工单挂接），支持从问题反查工单。

### 5.3 服务目录

两层结构：**目录**（分类，Gold/Silver/Bronze 分级）→ **服务项**。

- 服务项字段（10）：名称✔、所属目录✔、服务类型、负责人、描述、SLA 响应时限（小时）、SLA 解决时限（小时）、服务对象、状态（自动）、编号（自动）。
- 服务项年度工单量为实时统计展示，不录入。
- 维护权限由权限矩阵控制（默认 cio/admin）；全员可浏览（作为报单入口参考）。

### 5.4 CMDB 配置管理

单表 CI，9 个类别：应用 / 服务器 / 云资源 / 网络 / 安全 / 协作 / 终端 / 基础设施 / 咨询服务。

- 创建 4 必填：名称、类别、状态（默认运行中）、负责人。
- 可选：环境、业务负责人、供应商（关联供应商表）、描述、上线日期、备注。
- **类别专属属性**：每类预定义少量扩展属性（如应用：技术栈/部署方式；服务器：IP/配置），存 JSONB，折叠展示，全部可选。
- CI 关系：支持"运行于/依赖/连接"三种关系，用于影响分析（查看某 CI 时展示上下游）。
- 工单可关联 CI；CI 详情页反查关联工单历史。

### 5.5 SLA 管理

- **SLA 策略**（admin 配置）：按优先级 P1-P4 定义默认响应/解决时限；服务项可覆盖。
- **SLA 看板**（只读）：本月/本季各优先级达成率、超时工单清单、临期预警。全部实时计算。

### 5.6 供应商与合同

- 供应商（9 字段保留）：名称✔、联系人、电话、邮箱、服务范围、评级、状态、备注、编号（自动）。
- 合同：名称✔、供应商✔、金额、起止日期✔、负责人、状态（自动按日期推）、备注、附件。
- **到期预警**：距到期 90 天进 Dashboard 告警区并发通知。

### 5.7 知识库

- 发布仅 2 必填：**标题、正文**（Markdown）；可选：标签、关联工单。
- 自动：编号、作者、浏览数、"有用"数。
- 全文检索；工单详情页可一键"沉淀为知识"（带出工单上下文草稿）。
- 来源之三：需求关闭时经验沉淀一键转入。
- 发表知识、知识被点"有用"均产生积分事件。

## 6. 域三：项目管理

### 6.1 项目创建

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 名称 | ✔ | |
| 项目经理 | ✔ | 默认当前人 |
| 计划开始/结束 | ✔ | |
| 所属组合 | 可选 | 下拉选择已创建的项目组合（在"项目组合"标签页维护，见 6.5） |
| 描述 / 预算(万) / 关联服务项 | 可选 | 折叠 |

**或者：上传项目章程文档（.docx），系统解析自动生成项目 + WBS + 里程碑 + 风险草稿，用户仅确认修正**——推荐路径，解析失败时回退手工表单并提示原因。

自动：编号、状态、实际起止（状态流转打点）、进度（WBS 汇总）、健康度（规则：进度偏差 >15% 或里程碑逾期 → 黄；>30% 或红色风险 → 红）、实际成本（成本明细汇总）。

状态机：`规划中 → 进行中 → 已完成 → 已关闭`，可从进行中转"已暂停/已取消"。

### 6.2 项目详情 5 个标签页

| 标签页 | 内容 |
| --- | --- |
| 概述 | 基本信息 + 健康度 + 最新动态（一句话，随时更新）+ 关联需求 |
| 进度 | **甘特图**（按 WBS 起止渲染，含依赖线与里程碑标记）+ WBS 树 + 里程碑列表 |
| 成本 | 预算、成本明细录入（日期/金额/说明，极简 3 项）、自动汇总执行率、SPI/CPI 简化展示（按工期权重） |
| 风险 | 风险登记（标题/概率/影响/应对措施 4 项）、概率×影响矩阵图 |
| 文档 | 附件上传列表 + 章程导入入口 |

### 6.3 WBS 任务

- 创建 4 必填：任务名、负责人、开始/结束日期；可选：描述、交付物、前置任务。
- WBS 层级编码自动生成（按树位置）；状态更新即驱动进度（未开始 0% / 进行中 50% / 完成 100%）。
- 任务按期完成产生积分事件。

### 6.4 里程碑

名称✔、目标日期✔、说明；实际达成日期在达成时点一下；逾期自动告警。

### 6.5 项目组合（项目管理页内标签页）

项目管理主页面分两个标签页：**项目列表**（默认）和**项目组合**。

- 项目组合标签页：维护组合定义——名称✔、负责人、年度、描述；列表展示每个组合下的项目数与健康度分布。
- 创建项目时"所属组合"下拉选择已创建的组合名称（组合须先在此标签页创建）。
- Dashboard 与项目列表支持按组合筛选。

### 6.6 验收标准

- [ ] 手工建项目 ≤ 1 分钟；章程导入路径除确认外零手填
- [ ] 甘特图正确渲染 3 层 WBS 与依赖线
- [ ] 健康度/进度/成本执行率全自动，与明细数据一致
- [ ] 里程碑逾期次日出现在 Dashboard 告警区

## 7. 域四：需求管理（评估漏斗 · M10 升级）

### 7.1 五阶段生命周期

M10 起：在「登记」与「分析」间插入「评估」门——六维加权评分 + 四象限决策，只有决议为「立项」的需求才进入分析，形成需求漏斗。小需求可 `登记→分析` 跳过评估。

```text
登记 → 评估 → 分析 → 实现 → 关闭（可从任意在办阶段转"搁置/取消"）
```

| 阶段 | 谁 | 填什么 | 系统做什么 |
| --- | --- | --- | --- |
| ① 登记 | requester/it_bp/任意团队成员 | 标题✔、类型✔（业务/功能/数据/集成/合规）、所属业务✔、描述✔；来源/渠道部门/期望完成时间/期望效果/运营价值 可选 | 编号、提出人、登记时间自动；通知 it_pdm |
| ② 评估 | it_pdm + 评审（CIO/it_bm 知会） | 六维评分 D1-D6（1-5）、决议（立项/搁置/驳回）、备注 | **自动算加权总分与四象限**（不手填）；进入评估时间打点；评估门校验 |
| ③ 分析 | it_pdm | 负责人、排期目标日期、解决方案、验收标准（清单式）、PRD/开发人天；MoSCoW 降级为可选辅助标签 | 进入分析时间打点 |
| ④ 实现 | 负责人 | 任务分解（任务名/负责人/计划日期/计划·实际工天）、可选挂接项目 | 进度=已完成任务/总任务；任务完成产生积分 |
| ⑤ 关闭 | 负责人 | 逐条勾验收标准；**一键转出**：遗留问题→ITSM 问题、经验→知识库（自动带需求上下文） | 完成日期打点；交付周期计算；关闭产生积分 |

### 7.2 六维加权评分与四象限

依据《需求评分与优先级细化标准》（麦肯锡战略价值-执行可行性双轴）。权重/阈值/分档在**需求管理→「评分规则」标签页**配置（admin 可编辑，其他角色只读参考分档说明），年度可调（默认见下）。

| 维度 | 默认权重 | 说明 |
| --- | --- | --- |
| D1 战略对齐 / D2 业务价值 / D3 技术可行性 | 0.2 / 0.2 / 0.2 | 战略价值 + 技术 |
| D4 组织就绪 / D5 风险等级(反向) | 0.1 / 0.1 | 风险按 (6−D5) 反向计入 |
| D6 价值速度 | 0.2 | Time-to-Value |

`加权总分 = 0.2·D1 + 0.2·D2 + 0.2·D3 + 0.1·D4 + 0.1·(6−D5) + 0.2·D6`（服务端计算）。
四象限（横轴战略价值 (D1+D2)/2，纵轴总分，默认阈值 total 3.5 / strategic 4 / viable 3）：⭐战略下注、⚡速赢项目、📋低优先级、🔄重新评估。
评审治理：M10 起步为**单人共识评分**（`requirement_score.is_consensus` 回填需求六维分），多方独立评分+共识为后续增强（表已预留 reviewer_role/role_weight）。

### 7.3 需求列表与导入

- 按阶段分栏（看板，含「评估中」栏）+ 表格视图切换；筛选：业务线/优先级/**决议**/负责人/提出人；卡片展示加权总分与象限。
- **模板导入**：下载 Excel 模板（登记字段 + 可选六维分）→ 填写 → 上传，部分成功报错到行；已评满六维的行导入即落「评估中」并带分。

### 7.4 验收标准

- [ ] 登记 4 必填 ≤ 30 秒完成；评分字段只在评估阶段出现，不进登记表单
- [ ] 加权总分/象限全部服务端派生，用户不可手填
- [ ] 评估门：六维未评满或决议非「立项」时不允许进入分析
- [ ] 验收标准未全部勾选时不允许关闭（有遗留时必须转出问题或说明）
- [ ] 转出的问题/知识自动携带需求编号反向链接
- [ ] 全域中英双语；权重/阈值/分档 admin 可配

## 8. 域五：流程引擎（简化版）

**定位**：为工单/变更/需求/项目提供可配置的步骤化流程与自治级别标注，不做重装置。

- 三层模型：**流程定义**（含步骤：名称/顺序/默认角色/L1-L4 自治级别/SLA 时限）→ **流程实例**（单据触发）→ **流程任务**（步骤实例，指派到人）。
- 自治级别：L1 全自动 / L2 系统建议人确认 / L3 人做系统辅助 / L4 纯人工。用于流程监控展示与后续人效分析，不控制执行。
- 初始内置 6-8 个流程：事件处理、服务请求交付、变更审批实施、问题分析、需求交付、项目关键节点。
- 派单规则：按步骤默认岗位角色指派（如需求登记/业务对齐→it_bp、需求分析→it_pdm、项目节点→it_pm、变更实施→it_ops、开发任务→it_dev、变更风险评估→is_mgr），可在实例中改派，无外部依赖。
- **流程节点标准（M3.8，后续所有流程功能强制）**：每个节点可配置**处理人**（审批/执行，产生任务、阻塞流程）与**知会人**（仅站内通知，不产生任务、不阻塞，可多个角色/用户组）；流程定义页展示**流程示意图**（处理人蓝标/知会人灰标），编辑器实时预览。详见 docs/06 §十。
- 页面：流程定义管理（admin，含启停/编辑步骤）、流程监控（实例列表、卡点步骤、超时任务）。
- 单据详情页展示流程条（当前步骤高亮）。

**关于 n8n**：流程引擎内置于后端代码，不引入 n8n。理由：原系统 n8n 承担的四项职责中，文档自动生成已裁撤、飞书通知初期不接、按技能/负载派单简化为按角色指派、事件编排由通知发件箱覆盖；而 n8n 作为独立服务的部署维护与跨系统排障成本，正是旧系统复杂度的来源之一。**预留**：通知发件箱的事件流就是外部编排工具的挂接点，未来如需跨系统自动化，n8n 可订阅发件箱事件接入，业务代码零改动。

**验收**：新建工单自动创建对应流程实例；流程监控可见每个实例进行到哪一步；改派生效。

## 9. 域六：团队管理

### 9.1 人效管理（manager/admin）

- **规则可配置框架**：评分维度与权重后续由产品定义；引擎按周期（月/季）聚合以下输入源：工单（解决量/SLA 达成/满意度）、项目（任务按期率/里程碑）、需求（交付周期）、**成长积分**。
- 输出：周期评分表（人 × 维度 × 得分），纯计算态，可导出 CSV。
- v1 先交付数据聚合与展示框架 + 示例规则，正式规则上线前由产品确认。

### 9.2 成长积分

**核心机制：积分零录入，事件自动计分。**

| 来源 | 事件（分值全部可配，支持负分） |
| --- | --- |
| 服务贡献 | 工单解决、SLA 双达成、满意度 ≥4 星、问题根因定位 |
| 项目贡献 | WBS 任务按期完成、里程碑交付 |
| 需求贡献 | 需求任务完成、需求关闭 |
| 培训贡献 | 主讲/组织培训、参与培训 |
| 知识贡献 | 发表文章、文章被点"有用" |
| 建言献策 | 提出建言、被点赞、被采纳 |

- 积分流水：人/事件/分值/来源单据/时间，可追溯到触发单据；管理员手工加减分同样走流水（需填理由）。
- 页面：排行榜（月/季/年/累计）、个人积分明细、积分规则配置（admin）。
- 积分作为 9.1 人效评价输入源之一。

### 9.3 岗位编制

- 人员主数据：姓名✔、部门、岗位（关联岗位定义）、团队分组、状态（在岗/离职）、入职日期、技能标签。
- 岗位定义：岗位名✔、分工职责描述、编制数；页面呈现"编制 vs 在岗"缺口一览。
- 招聘需求：岗位✔、人数✔、状态（待招聘/面试中/已到岗/取消）、进度备注。

### 9.4 培训发展

- 活动登记 5 项：类型✔（内部交叉培训/外部技术交流/新技术研究）、主题✔、日期✔、主讲/组织人、参与人（多选）+ 可选产出链接。
- 登记完成自动为主讲人与参与人计积分。

### 9.5 团队文化

单页富文本管理：愿景、目标、工作行为准则（manager/admin 编辑，全员可见）。

### 9.6 建言献策

- 提交仅 2 项：标题✔、内容✔。
- 全员可浏览、点赞（每人每条一次）；manager 可标记"已采纳/已实现/已婉拒"。
- 提出/被点赞/被采纳自动计积分；被采纳的建言可一键转需求登记。

## 10. 支撑：系统管理（admin）

菜单结构（M3.9 定稿，6 入口）：

1. **组织管理**：「组织架构」标签页（公司→部门→人员三级树 + 右侧主数据面板；人员含 HR 基础字段——工号/性别/出生日期/用工类型/直属上级/办公地点，按飞书通讯录映射设计；**飞书为 Source of Truth**，同步记录的 HR 基础字段本地只读，仅岗位/技能/备注/部门类型可编辑；"从飞书同步"入口，凭据上线前配置）+「业务服务域」标签页（负责人 BM + 服务团队）。
2. **用户与组管理**：「用户」（账号/角色/认证源/开通默认角色）+「用户组」（专业线资源池：负责人 TM/组授予角色/成员）。
3. **角色与权限**：「角色定义」（内置 12 个可改名 + 自定义复制模板）+「预分配规则」（部门→首次开通默认角色）+「权限配置」（角色×30 模块×4 动作矩阵）。
4. **数据字典**（业务线/关闭代码/类别等下拉项 + 公司名等系统配置）。
5. **状态机配置**（每类单据的状态与流转规则可视化编辑，含在用状态删除保护）。
6. **审计日志**（admin/is_mgr/auditor 可查）。

另：SLA 策略在 ITSM-SLA 看板页维护；通知发件箱后台保留。

**流程定义管理**（流程中心）：流程/步骤全量可配置——步骤名称、默认指派（角色/用户组）、L1-L4 自治级别、步骤 SLA、触发条件（同类单据下激活流程的触发条件必须唯一）；已有实例的流程步骤锁定，通过**另存新版本**演进（老单据沿用旧版，新单据走新版）。
