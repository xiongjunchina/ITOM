# ADR-0002：以增量治理记录层适配 DMC 与数字化项目立项制度

- 状态：已接受
- 日期：2026-09-01
- 决策者：ITOM 产品负责人
- 适用范围：需求评估、项目立项、统一投入、报表和治理审计
- 英文镜像：[`docs/en/adr/0002-dmc-project-governance-alignment.md`](../en/adr/0002-dmc-project-governance-alignment.md)

## 背景

2026-09-01 定稿的 DMC 运作机制和数字化项目立项决策机制，确定了年度计划项目与计划外需求转项目的双轨治理，并明确了 30 万元、100 万元两个外部投资授权边界。制度要求需求评估关注战略对齐、业务价值、技术可行性、业务成熟度和风险五个维度，其中业务成熟度同时包含组织、人员和流程。

ITOM 已有需求评分、需求转项目、项目组合、统一投入、报表中心、流程审计和权限能力，但现行需求评分仍保留六维字段，项目尚未完整记录制度要求的来源、决策、预算状态、观察期和签署事实。与此同时，ITOM 的定位仍是平台产品与赋能组的管理工具，不应复制 DMC、财务、采购、流程、数据、安全或架构专业系统。

## 决策

采用“**增量治理记录层 + 既有领域事实复用**”方案：

1. 新需求采用五维评分；D4 正式命名为“业务成熟度”，融合组织、人员和流程；D6 仅作为历史兼容字段，不再进入新评估。
2. 不删除、不重算已有评分，不在普通用户界面展示评分版本变化；历史记录以只读方式保留。
3. 需求申请材料要求记录业务问题、预期结果、业务负责人、资源、边界/风险和业务成熟度；D1/D2评分依据和附件仍可记录但不强制。
4. 项目明确区分年度计划和计划外来源；计划外需求保留从评估、项目化判定到决策和项目的关联快照。
5. 增加 DMC 决策记录、金额口径、决策级别、条件、责任人、期限、检查时间、签署人和外部审批引用；首期不建设完整的在线 DMC 投票系统。
6. 投资授权金额只统计外部软件、硬件、云、咨询和实施投入；内部人力、管理成本和上线后运维成本单独进入统一投入和报表分析。
7. 项目生命周期增加预算待落实、阶段验收、观察期、价值评估、运维移交和关闭记录。
8. 继续复用统一投入台账和报表中心，不建立第二套账本或报表中心。
9. 财务、采购、法务、数据、安全、架构和流程系统继续作为专业事实来源；ITOM只保存受控引用、摘要和审计快照。
10. 所有新增字段、接口和治理记录均为增量设计，复用现有 RBAC、数据范围、流程、幂等和审计边界。

## 备选方案

### T1：在 ITOM 内建设完整 DMC 和项目投资管理系统

不采用。会复制会议、表决、预算、采购和专业审批能力，扩大 ITOM 边界并产生双主数据。

### T2：只在报表层解释制度，不增加治理记录

不采用。无法可靠记录计划外项目的决策级别、DMC条件、预算待落实、签署和观察期，报表会缺少可追溯事实。

### T3：增量治理记录层与既有领域事实复用

采用。改造范围可控，历史数据可保留，既能满足制度的可追溯要求，又不改变 ITOM 的平台型管理工具定位。

## 后果

### 正面后果

- 需求评分与正式制度统一为五维，业务成熟度同时覆盖组织、人员和流程；
- 年度项目、计划外需求、投资授权和 DMC 结论形成可追溯链路；
- 投资授权、内部人力和运行期成本可以分开分析；
- 报表中心可以直接产出 DMC 季度、半年度和年度管理视图；
- 专业系统仍保持事实权威，避免 ITOM 膨胀为全能系统。

### 代价与约束

- 需求和项目模型需要增加治理快照及兼容字段；
- DMC线下决策需要人工确认和记录，首期不会自动形成在线表决证据；
- 金额授权与统一投入必须使用不同聚合口径；
- 预算、签署、观察和价值评估会增加项目生命周期状态和测试复杂度。

## 风险与缓解

| 风险 | 缓解措施 |
|---|---|
| 历史六维评分被错误重算 | 保留旧字段和快照，新旧读取路径分离并增加回归测试 |
| DMC记录被误认为DMC正式事实 | 明确“线下决策、ITOM记录”，保存依据引用和记录人 |
| 授权金额与总投入混算 | 独立字段、分类和报表指标，禁止通过单一总额推导 |
| ITOM越界承接专业审批 | 只允许受控外部引用，不提供通用 HTTP/SQL/数据库写入 |
| 新治理字段破坏旧流程 | 所有扩展字段可空，旧项目和需求保持原流程行为 |

## 实施约束

P0 先完成五维评分、项目双轨、项目化判定、决策阈值和 DMC 记录；P1 再完成项目生命周期、投入口径和签署；P2 完成治理报表和受控专业系统引用。

进入编码前必须按仓库约定确认 `feature-local` 路线并建立验收矩阵；实现、测试、中文权威文档和英文镜像必须同批交付。当前 ADR 和映射文档不启动本地应用、不改变数据库、不触发 GitHub 或 IDC 操作。
