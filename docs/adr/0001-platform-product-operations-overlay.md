# ADR-0001：以可选扩展档案与受控观测台账建设平台产品运营中枢

- 状态：已接受
- 日期：2026-08-31
- 决策者：ITOM 产品负责人
- 适用范围：平台产品与赋能组运营管理能力
- 英文镜像：[`docs/en/adr/0001-platform-product-operations-overlay.md`](../en/adr/0001-platform-product-operations-overlay.md)

## 背景

ITOM 需要适配 FDSE 与平台型团队协作方式，但其定位是平台产品与赋能组的管理工具，而不是承载流程、数据、AI、集成和架构团队的全部专业职能。现有系统已经具备服务目录、需求、项目、ITSM、统一投入、报表、权限、审计和领域服务边界；直接复制这些领域会形成双主数据和重复流程。

同时，平台运营需要新增平台产品负责人、生命周期、需求归属、容量计划、正式承诺、赋能资产、外部专业记录引用、指标观测和数据质量等语义。需要在复用现有能力与保持专业系统权威之间做出架构选择。

## 决策

采用“**可选扩展档案 + 受控观测台账**”方案：

1. `ServiceItem` 和 `Requirement` 继续分别作为服务与需求的唯一主记录；
2. 通过可选 1:1 档案增加平台服务和平台需求管理语义，未启用档案的记录保持原行为；
3. 在 ITOM 内新增版本化容量计划、容量承诺、赋能资产和服务目标；
4. 专业流程、数据、AI、集成和架构系统继续作为其专业事实的 System of Record；
5. ITOM 只保存外部系统登记、稳定外部引用、同步运行和带来源/公式/质量的指标观测；
6. 第一阶段外部接入默认为只读，不提供通用任意 HTTP、SQL、Shell 或数据库写入连接器；
7. 平台分析扩展现有统一报表中心，不建立第二套报表中心；
8. 统一投入台账继续是预算、费用、工时和分摊的唯一内部台账；
9. 现有身份、组织、RBAC、数据范围、审计、工作流、幂等、示例只读和领域服务边界继续生效；
10. 本决策不新增 Aily、MCP 或 Web Agent 工具。未来智能能力必须单独设计、批准，并通过代码注册的领域服务能力实现。

所有新增表和接口均为增量设计。不得自动把全部服务项或需求标记为平台记录，也不得通过批量回填推断业务含义。

## 备选方案

### T1：直接向服务项与需求增加全部平台字段

不采用。该方案实现路径短，但会让所有服务项和需求承担平台产品语义，增加空字段、迁移、权限和发布耦合，也不利于分批启用。

### T2：可选扩展档案与受控观测台账

采用。该方案复用既有领域主记录，以增量模型隔离新语义；外部专业事实保留在源系统，ITOM 只建立可审计的管理视图，适合按 P0–P2 分阶段交付。

### T3：建立独立完整的平台管理子系统

不采用。该方案会重复服务、需求、项目、投入、报表、身份和权限能力，造成双主数据、跨域同步和更高维护成本，超出 ITOM 的管理工具定位。

## 后果

### 正面后果

- 现有服务目录、需求、投入和报表投资得到最大复用；
- 未参与平台运营的记录无行为变化，迁移范围可控；
- 内部与外部事实边界清晰，指标可以追溯到来源和同步运行；
- 平台运营可以按服务、需求、容量、投入、采纳和可靠性形成闭环；
- 后续连接器可以按具体系统逐个评估和授权。

### 代价与约束

- 查询和报表需要跨基础记录、扩展档案、投入与观测聚合；
- 平台产品经理需要显式启用和治理档案，不能依赖无审核自动回填；
- 外部指标必须处理新鲜度、冲突、错误、无数据和公式版本；
- 容量计划引入版本、审批、并发和超容量例外控制；
- 每个具体连接器都需要单独的契约、安全和运行设计。

## 风险与缓解

| 风险 | 缓解措施 |
|---|---|
| 把 ITOM 扩张为专业执行系统 | 坚持 System of Record 矩阵与非目标；连接器只汇聚管理摘要和证据 |
| 双主数据或语义漂移 | 复用 `ServiceItem`、`Requirement` 和统一投入；扩展档案只保存附加语义 |
| 外部数据被误认为实时正确 | 显示来源时间、接收时间、质量和新鲜度；`stale/error/conflict/no_data` 显式呈现 |
| 超容量承诺失控 | 默认拒绝超净容量；CIO 例外需要理由、审批和审计 |
| 权限越界 | 复用现有功能权限、敏感权限和数据范围；管理员不替代业务审批 |
| 智能体绕过领域规则 | 不新增通用工具；未来能力必须调用领域服务并通过单独批准 |

## 实施约束

首个实现候选只覆盖 P0-1 至 P0-4：平台服务档案、平台需求池、季度容量与承诺、现有报表中心的平台基础分析。外部连接器、外部指标观测和 Web Agent 能力不在 P0 内。

截至本 ADR 接受时，实现尚未开始。进入开发前必须单独确认仓库规定的任务路线，并建立代码、测试、中文权威文档和英文镜像一致的验收矩阵。
